gh-worker

A lightweight HTTP worker that executes shell commands on demand

A single-file Express 5 service exposing a REST endpoint to run shell commands remotely, with API-key auth, CORS control, timeouts, and chained execution. Built for CI/CD hooks, automation, and remote tooling.

Express 5 TypeScript Node.js Single-file No deps beyond express © 2026 MIT License

Overview

gh-worker is a minimal HTTP worker that runs shell commands submitted through a JSON API. The entire server lives in src/index.ts — there is no package boundary, no database, no build pipeline beyond tsc.

It is designed to sit behind a webhook or automation pipeline: a CI job, a GitHub Action, a chat bot, or any client that needs to trigger shell commands on a host. The worker authenticates each request with an API key, runs the command via child_process.exec, and returns stdout/stderr/exit code as JSON.

Single command

Send { command, args } and the worker runs one command with escaped arguments.

Chained commands

Send { commands: [...] } and they run with && — fail-fast.

Working directory

Optional cwd sets where the command runs.

Timeouts

Every command is killed after executionTimeoutMs (default 30s).

Features

  • API-key authentication — every /execute request requires an X-API-Key header matching a configured key.
  • CORS allowlist — only origins listed in allowedOrigins get CORS headers; otherwise requests still work but without browser CORS permission.
  • Config from file or CLI — config.json at the repo root, overridable by CLI flags. SIGHUP reloads config without a restart.
  • Two request modes — single command with auto-escaped args, or a chain of commands joined with &&.
  • Structured JSON responses — success, stdout, stderr, error, exitCode on every reply.
  • Health endpoint — GET /health returns { status: "ok" } for load balancers and uptime checks.
  • Zero external runtime deps — only express.

Quick Start

1. Install dependencies

npm install

2. Configure API keys

Edit config.json in the repo root and replace the placeholder keys:

{
  "apiKeys": [
    "your-secret-key-1"
  ],
  "allowedOrigins": [
    "http://localhost:3000"
  ],
  "executionTimeoutMs": 30000,
  "port": 8080
}
Required: The server exits with code 1 if zero API keys are configured. You must set at least one key via config.json or the --api-key flag.

3. Run the server

Development (with hot TypeScript via ts-node):

npm run dev

Production (compile first, then run):

npm run build
npm start

You should see:

Worker running on port 8080
Timeout: 30000ms
Allowed origins: http://localhost:3000

4. Test it

curl http://localhost:8080/execute \
  -H "Content-Type: application/json" \
  -H "X-API-Key: your-secret-key-1" \
  -d '{"command":"echo","args":["hello world"]}'

Response:

{
  "success": true,
  "stdout": "hello world\n",
  "stderr": "",
  "exitCode": 0
}

Configuration

Config is loaded from config.json at the repo root (resolved relative to __dirname, i.e. next to the running JS file). CLI flags override file values. If the file is missing, defaults apply — except apiKeys, which defaults to [] and causes the server to exit.

FieldTypeDefault (no file)Description
apiKeysstring[][] ⚠️Keys accepted in the X-API-Key header. Empty array = server won't start.
allowedOriginsstring[]["*"]Origins that receive CORS headers. Only listed origins get Access-Control-Allow-Origin.
executionTimeoutMsnumber30000Hard timeout per command in milliseconds.
portnumber8080HTTP listen port.
Live reload: Send SIGHUP to the process to reload config.json without restarting. CLI flags passed at startup still take precedence over the reloaded file values. 
kill -HUP <pid>

CLI Flags

All flags are optional and override config.json.

FlagShortDescription

Endpoints

MethodPathAuthPurpose
POST/executeYesRun one or more shell commands
GET/healthNoHealth check for uptime monitoring
OPTIONSanyNoCORS preflight (returns 204)

POST /execute

Runs shell commands and returns the result as JSON. Requires the X-API-Key header.

Request body

Two modes — send either command or commands:

Mode 1 — Single command

{
  "command": "echo",
  "args": ["hello world", "foo bar"],
  "cwd": "/tmp"
}

Each arg is single-quote-escaped and appended to the command. The above becomes:

echo 'hello world' 'foo bar'

Mode 2 — Chained commands

{
  "commands": [
    "git pull",
    "npm install",
    "npm run build"
  ],
  "cwd": "/home/user/myapp"
}

Commands are joined with && (fail-fast — if one fails, the rest don't run):

git pull && npm install && npm run build

Headers

HeaderRequiredDescription
Content-TypeYesapplication/json
X-API-KeyYesMust match a configured key

Response

Success (exit code 0)
{
  "success": true,
  "stdout": "...\n",
  "stderr": "",
  "exitCode": 0
}
Failure (non-zero exit)
{
  "success": false,
  "stdout": "partial output...\n",
  "stderr": "command not found\n",
  "error": "Command failed: ...",
  "exitCode": 127
}
Bad request (no command)
400 { "error": "command or commands is required" }
Unauthorized (missing/invalid key)
401 { "error": "Invalid or missing API key" }

GET /health

No authentication required. Useful for load balancers, Docker healthchecks, and uptime monitors.

curl http://localhost:8080/health
{ "status": "ok" }

Integration

Examples in common languages and tools. Replace YOUR_API_KEY and http://localhost:8080 with your values.

Single command

curl http://localhost:8080/execute \
  -H "Content-Type: application/json" \
  -H "X-API-Key: YOUR_API_KEY" \
  -d '{"command":"echo","args":["hello"]}'

Chained commands

curl http://localhost:8080/execute \
  -H "Content-Type: application/json" \
  -H "X-API-Key: YOUR_API_KEY" \
  -d '{"commands":["git pull","npm ci","npm run build"],"cwd":"/app"}'

Browser fetch

const res = await fetch("http://localhost:8080/execute", {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    "X-API-Key": "YOUR_API_KEY"
  },
  body: JSON.stringify({
    command: "echo",
    args: ["hello from browser"]
  })
});
const data = await res.json();
console.log(data);
CORS: The browser origin must be listed in allowedOrigins for the response to be readable from JavaScript. Otherwise the browser blocks it.

Node.js (fetch)

const res = await fetch("http://localhost:8080/execute", {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    "X-API-Key": process.env.WORKER_API_KEY
  },
  body: JSON.stringify({
    commands: ["git pull", "npm ci", "npm test"],
    cwd: "/home/user/project"
  })
});
const result = await res.json();
if (!result.success) {
  console.error("Failed:", result.error);
  process.exit(1);
}
console.log(result.stdout);

Python (requests)

import requests

resp = requests.post(
    "http://localhost:8080/execute",
    headers={
        "Content-Type": "application/json",
        "X-API-Key": "YOUR_API_KEY",
    },
    json={
        "commands": ["git pull", "npm ci", "npm run build"],
        "cwd": "/app",
    },
)
data = resp.json()
if data["success"]:
    print(data["stdout"])
else:
    print(f"Failed (exit {data['exitCode']}): {data['error']}")
    print(data["stderr"])

Python (stdlib urllib)

import json, urllib.request

req = urllib.request.Request(
    "http://localhost:8080/execute",
    data=json.dumps({"command": "uname", "args": ["-a"]}).encode(),
    headers={
        "Content-Type": "application/json",
        "X-API-Key": "YOUR_API_KEY",
    },
)
with urllib.request.urlopen(req) as r:
    print(json.loads(r.read()))

GitHub Actions step

- name: Trigger remote build
  run: |
    curl -sSf http://your-worker-host:8080/execute \
      -H "Content-Type: application/json" \
      -H "X-API-Key: ${{ secrets.WORKER_API_KEY }}" \

Security

Important: This worker executes arbitrary shell commands. Treat it as a privileged service.
  • Never expose it to the public internet without a reverse proxy, TLS, and network restrictions. It runs whatever command the authenticated caller sends.
  • Rotate the placeholder keys. config.json ships with change-me-key-* — replace them before any real use.
  • Restrict allowedOrigins to only the domains that need to call it from a browser. Leaving * (the no-file default) allows any origin to receive CORS headers.
  • Run as a non-root user in production so executed commands inherit least privilege.
  • Keep API keys out of client code. In browser apps, proxy requests through your own backend rather than embedding the key in JavaScript.
  • There is no command allowlist. Any authenticated key can run any command. If you need scoping, run multiple workers with different keys and filesystem isolation.

Full Examples

Deploy a Node app on push

curl -X POST http://localhost:8080/execute \
  -H "Content-Type: application/json" \
  -H "X-API-Key: $KEY" \
  -d '{
    "commands": [
      "git fetch --all",
      "git reset --hard origin/main",
      "npm ci",
      "npm run build",
      "pm2 restart myapp"
    ],
    "cwd": "/var/www/myapp"
  }'

Run a backup script with a timeout

curl -X POST http://localhost:8080/execute \
  -H "Content-Type: application/json" \
  -H "X-API-Key: $KEY" \
  -d '{
    "command": "/opt/scripts/backup.sh",
    "args": ["--full", "--compress"],
    "cwd": "/var/backups"
  }'

Check system info

curl http://localhost:8080/execute \
  -H "X-API-Key: $KEY" \
  -H "Content-Type: application/json" \
  -d '{"command":"uname","args":["-a"]}'
{
  "success": true,
  "stdout": "Linux host 6.5.0-arch #1 SMP x86_64 GNU/Linux\n",
  "stderr": "",
  "exitCode": 0
}

Notes

  • Single file: All server logic is in src/index.ts. There is no router, controller, or service layer split.
  • No tests, lint, or CI. Don't assume npm test works — there is no test script.
  • dist/ is a build artifact (gitignored). Don't edit it; edit src/ and rebuild.
  • index.html at the repo root is unrelated. It's an untracked UI demo ("What-If Money Advisor") and is not served by the worker.
  • TypeScript strict mode with ES2022 target and commonjs modules. resolveJsonModule is enabled, though config is read via fs at runtime rather than imported.
  • Args escaping: Single quotes are escaped as '\''. This handles most cases but is not a sandbox — the worker trusts the authenticated caller.
  • Timeouts kill the child process via child_process.exec's built-in timeout option. A timed-out command returns success: false with an error message.
